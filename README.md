# HTML 하나를 선택해 개별 페이지 게시하기

## 원하는 3단계

1. **Actions → Publish HTML page → Run workflow**에서 `input_path`에 HTML 경로를 직접 입력합니다. 기본으로 `public/`이 적혀 있으므로 뒤에 파일명을 붙여 `public/test1.html`처럼 완성합니다.
2. **Run workflow**를 누르면 선택한 HTML만 새로 게시하거나 갱신합니다. 이전에 게시한 다른 페이지는 보관된 내용 그대로 유지됩니다. HTML 업로드만으로는 게시되지 않습니다.
3. 실행 결과의 **deploy 상자 링크** 또는 **deploy summary → 이용자에게 전달할 결과 링크**를 누릅니다. 이번에 선택한 파일의 링크 하나만 표시됩니다.

예: `public/test1.html` → https://kdh2110.github.io/html-deploy/test1/

주소에는 `.html`이 없으며 마지막 `/`는 붙습니다. 같은 파일을 다시 실행하면 같은 주소의 내용이 바뀝니다. 과거 버전도 별도로 남기려면 새 파일명을 사용하세요. 폴더가 있다면 주소에도 폴더가 유지됩니다.

## 게시 전 파일 준비

완성된 HTML을 `public/`에 넣습니다. 별도의 JSON, CSS, JavaScript, 이미지가 있다면 기대하는 상대 경로에 함께 넣으세요. 선택하지 않은 다른 HTML은 새로 게시하지 않습니다. 각 게시 시 public/의 비HTML 보조 파일을 해당 페이지 전용 공간에 복사하여 다른 페이지 게시로 기존 데이터가 바뀌지 않게 합니다. 공개할 보조 파일만 public/에 넣으세요.

기존 게시 결과는 **published-pages 브랜치**에 누적 보관합니다. 해당 브랜치의 `site/`와 `registry.json`을 삭제하지 마세요. main에서 원본 HTML을 수정하거나 삭제해도 이미 게시한 페이지는 다음 선택 게시 전까지 유지됩니다. 배포 실패 시에도 준비된 결과가 보관 브랜치에 남을 수 있으며 다음 배포 때 포함됩니다.

공개 메인 페이지에는 목록이 없습니다. 각 실행 결과에도 그 실행의 링크 하나만 나옵니다. 저장소가 공개라면 저장소 및 Actions 실행 기록은 다른 사람도 볼 수 있습니다.

## 경로 입력

입력란은 하나이며 기본값은 `public/`입니다. 파일명과 확장자까지 입력하세요.

- `public/test1.html` → `/html-deploy/test1/`
- `public/reports/example.html` → `/html-deploy/reports/example/`

`public/`만 입력하거나 없는 파일을 지정하면 오류 메시지를 표시하고 게시하지 않습니다.
드롭다운 및 자동 목록 갱신 작업은 사용하지 않으며, 별도 개인 토큰 설정도 필요하지 않습니다.

## 사용 시 참고

- 선택은 게시 대상 결정용입니다. 다른 HTML의 미게시 수정 내용은 반영하지 않습니다.
- 같은 주소가 되는 `a.html`과 `a.htm`은 동시에 게시할 수 없습니다.
- UTF-8 HTML을 지원합니다. `<base>`로 일반적인 상대 경로 자원을 유지합니다. `location.pathname`에 의존하는 코드, 특정 경로에 고정된 링크, 페이지 내 앵커는 별도 조정이 필요할 수 있습니다.
- 기존 `.html` 주소가 있다면 유지합니다. 새로 공유할 주소는 결과 화면의 확장자 없는 링크를 사용하세요.
- 공개 사이트 전체 크기는 1 GB 이내여야 합니다. 페이지별 보조 파일 복사본도 용량에 포함됩니다.
- Run workflow의 Branch는 기본 브랜치 `main`을 사용하세요.

검증: `python3 -m unittest discover -s tests -v`
